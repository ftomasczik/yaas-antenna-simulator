# YAAS 0.3.0

- Fecha: 2026-09-27
- Rama: `feat/real-ground` (fase 7B) y `chore/rename-to-yaas`
  (identidad YAAS)

Esta es la **primera release pública con identidad YAAS**: la fase
7B (tierra real Sommerfeld-Norton) se desarrolló bajo el nombre de
desarrollo anterior, AntSim, y el proyecto completo se renombró a
YAAS antes de esta versión llegar a publicarse externamente. No
existe ninguna versión publicada bajo el nombre "AntSim 0.3.0". Ver
`docs/decisions/0008-rename-to-yaas.md` para el detalle completo del
cambio de nombre.

Esta versión también deja lista la publicación pública en lo que
respecta a licencia y avisos de terceros: GPL-3.0-only definitiva
(ADR 0004), `LICENSE`, `THIRD_PARTY_NOTICES.md` y la política de
distribución binaria (`docs/packaging/windows-release-compliance.md`).
La primera publicación pública prevista de este repositorio es
**solo de código fuente**: `dist\yaas.exe` no se publicará todavía
como asset descargable (ver sección 11).

## 1. Resumen ejecutivo

YAAS 0.3.0 agrega un tercer entorno de simulación, **tierra real
homogénea mediante el método Sommerfeld-Norton**, sobre los dos
entornos ya existentes desde 0.2.0 (espacio libre y tierra
perfectamente conductora), de punta a punta: dominio, esquema de
proyecto `.yaas` (nueva versión 3), motor PyNEC/NEC2++ (con una
estrategia de barrido dedicada), exportación NEC, un proyecto de
ejemplo real y validación cruzada independiente contra 4nec2.
Además, esta versión incorpora el cambio completo de identidad
técnica de AntSim a YAAS (ver sección 10). Ver `CHANGELOG.md` para
el detalle completo y `docs/phases/phase-7b-real-ground.md` para el
cierre de fase técnico de tierra real (redactado bajo el nombre de
desarrollo AntSim).

## 2. Nueva capacidad: tierra real

Un proyecto puede declarar ahora `RealGroundEnvironment`, con:

- `model`: por ahora, un único valor, `RealGroundModel.SOMMERFELD_NORTON`
  (el método rápido por coeficiente de reflexión/Fresnel queda fuera
  de esta versión: la investigación previa encontró resultados sin
  sentido físico para conductores cercanos al plano de tierra con ese
  método);
- `relative_permittivity`: permitividad relativa del suelo, debe ser
  finita y estrictamente positiva;
- `conductivity_s_per_m`: conductividad del suelo en siemens por
  metro (S/m), debe ser finita y mayor o igual a cero — `0.0` se
  admite explícitamente, como un dieléctrico homogéneo sin pérdidas,
  distinto de "no hay tierra" (eso se sigue expresando con
  `FreeSpaceEnvironment`).

La validación geométrica ya existente desde 0.2.0 se aplica sin
cambios: con tierra real (igual que con tierra perfecta), todo
conductor debe cumplir `z >= 0`, y ningún conductor puede quedar
completamente contenido en el plano de tierra (`z = 0` en ambos
extremos) — esos casos se rechazan con un `ValueError` claro que
identifica el conductor, antes de llegar a PyNEC.

## 3. Estrategia de simulación

`PyNecEngine` configura tierra real con:

```python
geometry_complete(1)
gn_card(2, 0, relative_permittivity, conductivity_s_per_m, 0, 0, 0, 0)
```

mismo orden ya usado por espacio libre y tierra perfecta (conductores,
luego `GE`, luego `GN`).

Para barridos, espacio libre y tierra perfecta conservan la estrategia
histórica (un único contexto NEC2++ reutilizado con `fr_card`
multipunto); **tierra real crea un contexto NEC2++ completamente
nuevo por cada frecuencia**. Razón: la investigación previa encontró
que, para un conductor alimentado justo en el plano de tierra (z=0),
reutilizar un único contexto puede introducir una discrepancia
sistemática y no despreciable (~0.6-0.9 Ω) frente al cálculo
independiente por frecuencia; para geometrías elevadas la discrepancia
es despreciable (~1e-7 Ω), pero YAAS no puede garantizar que todo
proyecto de tierra real mantenga sus conductores lejos del plano — un
monopolo alimentado en la base es un caso de uso legítimo. La
estrategia más segura se aplica entonces de forma general, sin
distinguir por geometría.

Costo temporal esperado: la estrategia de contexto nuevo por
frecuencia **no es más lenta** que reutilizar un único contexto (el
tiempo está dominado por el propio cálculo de Sommerfeld-Norton,
~40 ms/punto, no por la creación del contexto). Un barrido de 81
puntos tarda aproximadamente 3.4 segundos de cómputo puro (~5 segundos
a través del ejecutable, incluido el arranque del proceso).

## 4. Esquema v3

- **v1**: sin `simulation.environment`; se interpreta siempre como
  espacio libre; conserva `schema_version == 1` en memoria.
- **v2**: `simulation.environment` obligatorio; admite únicamente
  `free_space` o `perfect_ground`; `real_ground` se rechaza
  explícitamente bajo v2.
- **v3** (nueva en esta versión): admite además `real_ground`:

```json
"environment": {
  "kind": "real_ground",
  "model": "sommerfeld_norton",
  "relative_permittivity": 13.0,
  "conductivity_s_per_m": 0.005
}
```

sin claves adicionales ni faltantes.

**Migración**: el escritor siempre genera esquema versión 3, sin
importar el `schema_version` del objeto en memoria. Guardar un
proyecto leído de un archivo v1 o v2 lo migra automáticamente a v3;
guardar no modifica el objeto `AntennaProject` recibido (es
inmutable). **Compatibilidad hacia atrás, no hacia adelante**: el
lector de YAAS 0.3.0 puede abrir v1, v2 y v3, pero una versión
anterior (publicada como AntSim 0.1.x/0.2.0) no reconoce
`real_ground` como `kind` válido.

## 5. Exportación NEC

`gn_card()` en PyNEC recibe **8 argumentos posicionales**
(`ground_type, rad_wire_count, F1, F2, F3, F4, F5, F6`). La tarjeta
`GN` de texto tiene siempre **4 campos enteros (I1-I4) seguidos de 6
campos flotantes (F1-F6)** — **10 valores en total**, con I3/I4
reservados en blanco (que `gn_card()` ni siquiera expone). Copiar
literalmente la cantidad de argumentos de `gn_card()` a la tarjeta de
texto produce un archivo mal formado.

Para tierra real (`relative_permittivity=13.0`,
`conductivity_s_per_m=0.005`), la exportación NEC (`yaas export-nec`)
agrega, siempre después de la última tarjeta `GW` y antes de
`EX`/`FR`:

```text
GE 1
GN 2 0 0 0 13 0.005 0 0 0 0
```

## 6. Ejemplo nuevo

`examples/dipole-20m-real-ground.yaas`: un dipolo horizontal (mismo
brazo de 5.03 m que el dipolo de referencia), elevado 10 m sobre el
plano de tierra, 101 segmentos, alimentado en el segmento 51 a
14.150 MHz, sobre tierra real (`relative_permittivity=13.0`,
`conductivity_s_per_m=0.005`, Sommerfeld-Norton).

## 7. Validación

A 14.150 MHz:

| Motor | Impedancia | ROE (50 ohm) |
|---|---:|---:|
| YAAS / PyNEC | 66.57 - j41.36 ohm | 2.13 |
| 4nec2 V5.9.3 | 66.6 - j41.4 ohm | 2.13 |

Barrido de 81 puntos (13.5-15.5 MHz):

- Resonancia aproximada: 14.550 MHz, 70.40 - j1.00 ohm, ROE 1.41.
- ROE mínima: 1.41, a 14.550 MHz.
- Ancho de banda para ROE <= 2.00: 14.200-14.900 MHz (700.0 kHz,
  4.81 % porcentual), sin truncamiento.

Detalle completo, incluida la comparación punto a punto contra 4nec2
en 13.5/14.5/15.5 MHz, en
`docs/validation/real-ground-dipole-4nec2.md`.

Verificación: 634 pruebas automatizadas (628 de la fase 7B más 6 del
cambio de identidad a YAAS) y una ejecución completa del build de
Windows (`scripts/build_windows.ps1`), con smoke tests del ejecutable
PyInstaller real (`dist\yaas.exe`) para los proyectos de ejemplo de
los tres esquemas (1, 2 y 3).

## 8. Compatibilidad y limitaciones

- **Sin ruptura para la lectura de proyectos v1/v2**: ambos siguen
  cargando exactamente igual que en 0.2.0.
- Tierra perfecta y espacio libre no cambian: mismos resultados,
  misma exportación NEC (`GE 0` sin `GN` para espacio libre;
  `GE 1`/`GN 1 0 0 0 0 0 0 0` para tierra perfecta).
- Los modelos MMANA-GAL con cualquier tipo de tierra (perfecta o
  real) continúan rechazándose en la importación
  (`yaas import-mmana`); solo se importan modelos de espacio libre.
- El método rápido de tierra real por coeficiente de reflexión
  (Fresnel) todavía no está soportado.
- No hay radiales, pantallas de tierra ni conductores enterrados,
  para ningún tipo de tierra.
- Los barridos de tierra real no ofrecen progreso ni cancelación: un
  barrido de 81 puntos puede tardar varios segundos.
- No se calculan patrones de radiación ni ganancia.
- No existe todavía una interfaz gráfica.

## 10. Cambio de identidad: AntSim → YAAS

Antes de esta publicación, el proyecto se renombró por completo de
AntSim a **YAAS (Yet Another Antenna Simulator)**, sin alias ni
compatibilidad con los nombres anteriores (ver
`docs/decisions/0008-rename-to-yaas.md`):

| Elemento | Antes (AntSim) | Ahora (YAAS) |
|---|---|---|
| Distribución Python | `antenna-simulator` | `yet-another-antenna-simulator` |
| Módulo | `antsim` | `yaas` |
| Comando CLI | `antsim` | `yaas` |
| Ejecutable | `antsim.exe` | `yaas.exe` |
| Dominio gettext | `antsim` | `yaas` |
| Variable de entorno | `ANTSIM_LANGUAGE` | `YAAS_LANGUAGE` |
| Extensión de proyecto | `.antsim` | `.yaas` |

`schema_version` (1/2/3) y el contenido JSON de los proyectos no
cambian: la extensión y la marca son independientes del contrato del
formato. Los tres ejemplos históricos de esquema (v1, v2 y v3) se
renombraron a `.yaas` conservando su contenido byte a byte.
