# AntSim 0.2.0

- Fecha: 2026-09-27
- Rama: `feat/perfect-ground`

## 1. Resumen ejecutivo

AntSim 0.2.0 agrega un modelo de entorno de simulación, con soporte
inicial de **tierra perfectamente conductora** además del espacio
libre ya existente, de punta a punta: dominio, esquema de proyecto
`.antsim` (nueva versión 2), motor PyNEC/NEC2++, exportación NEC, un
proyecto de ejemplo real y validación cruzada independiente contra
teoría de imágenes y 4nec2. Ver `CHANGELOG.md` para el detalle
completo y `docs/phases/phase-7a-perfect-ground.md` para el cierre de
fase técnico.

## 2. Nueva capacidad: tierra perfecta

Un proyecto puede declarar ahora `PerfectGroundEnvironment` (plano de
tierra perfectamente conductor en z=0) además de
`FreeSpaceEnvironment` (el único entorno que existía hasta 0.1.1).
Cuando el entorno no es espacio libre, el dominio valida que ningún
conductor cruce o quede bajo el plano de tierra, ni quede contenido
por completo en él (z=0 en ambos extremos): esos casos se rechazan
con un `ValueError` claro que identifica el conductor, en vez de
llegar a NEC2++ y producir una excepción nativa opaca.

## 3. Esquema v2 y contrato de `environment`

El esquema `.antsim` versión 2 agrega `simulation.environment`,
obligatorio, con exactamente dos formas válidas:

```json
"environment": {"kind": "free_space"}
```

o

```json
"environment": {"kind": "perfect_ground"}
```

No se admiten claves adicionales dentro de `environment` ni un
`kind` distinto de esos dos valores.

## 4. Compatibilidad y migración desde v1

- Un archivo del esquema 1 (sin `simulation.environment`, como todos
  los proyectos existentes hasta 0.1.1) **sigue cargando sin
  cambios** y se interpreta siempre como espacio libre.
- El objeto cargado en memoria conserva `schema_version == 1`
  mientras no se vuelva a guardar.
- Al guardarse con esta versión de AntSim, **cualquier proyecto se
  escribe siempre en el esquema 2**, incluido `simulation.environment`
  explícito: un proyecto v1 guardado queda migrado a v2
  automáticamente, sin intervención manual.
- Guardar un proyecto no modifica el objeto en memoria que se le pasa
  al escritor (es inmutable).
- **Compatibilidad hacia atrás, no hacia adelante**: el lector nuevo
  de AntSim 0.2.0 puede abrir tanto v1 como v2, pero **AntSim 0.1.1
  no puede abrir un proyecto v2** (no reconoce `simulation.environment`
  como campo esperado). Un proyecto migrado a v2 no debe abrirse con
  una versión anterior de AntSim.

## 5. PyNEC y exportación NEC

`PyNecEngine` configura tierra perfecta con
`geometry_complete(1)` seguido de `gn_card(1, 0, 0, 0, 0, 0, 0, 0)`.
La exportación NEC (`antsim export-nec`) agrega, para ese entorno,
las tarjetas:

```text
GE 1
GN 1 0 0 0 0 0 0 0
```

siempre después de la última tarjeta `GW` y antes de `EX`/`FR`. Para
espacio libre, la salida se mantiene **exactamente igual que antes**
de esta versión: `GE 0`, sin ninguna tarjeta `GN`.

## 6. Ejemplo nuevo

`examples/monopole-20m-perfect-ground.antsim`: un monopolo vertical
cuarto de onda (mismo brazo de 5.03 m que el dipolo de referencia),
alimentado en la base contra tierra perfecta, 38 segmentos, a
14.150 MHz.

## 7. Validación analítica y con 4nec2

Un monopolo cuarto de onda sobre tierra perfecta es, por teoría de
imágenes, eléctricamente equivalente a la mitad de un dipolo de media
onda en espacio libre. Se comparó esa predicción independiente contra
AntSim/PyNEC y contra 4nec2 V5.9.3 con el mismo archivo NEC exportado.
Detalle completo en
`docs/validation/monopole-perfect-ground-4nec2.md`.

## 8. Resultados numéricos principales

| Fuente | Impedancia | ROE (50 ohm) |
|---|---:|---:|
| Predicción por teoría de imágenes | 33.72 - j15.63 ohm | — |
| AntSim / PyNEC | 33.79 - j15.62 ohm | 1.72 |
| 4nec2 V5.9.3 | 33.8 - j15.6 ohm | 1.72 |

Geometría: 38 segmentos. Verificación: 522 pruebas automatizadas y
una ejecución completa del build de Windows
(`scripts/build_windows.ps1`), con smoke tests del ejecutable
PyInstaller real para los proyectos de ejemplo de ambos esquemas (1 y
2).

## 9. Comandos de verificación (CLI)

```powershell
antsim --version
antsim doctor

antsim validate .\examples\monopole-20m-perfect-ground.antsim
antsim simulate .\examples\monopole-20m-perfect-ground.antsim
antsim sweep .\examples\monopole-20m-perfect-ground.antsim

antsim export-nec `
    .\examples\monopole-20m-perfect-ground.antsim `
    .\monopole-20m-perfect-ground.nec

antsim export-nec `
    --sweep `
    .\examples\monopole-20m-perfect-ground.antsim `
    .\monopole-20m-perfect-ground-sweep.nec
```

## 10. Actualización desde 0.1.1

```powershell
git pull
python -m pip install -e ".[dev]"
.\scripts\build_windows.ps1
```

Los proyectos `.antsim` existentes (esquema 1) siguen funcionando sin
cambios; quedan migrados al esquema 2 la próxima vez que se guarden
con esta versión de AntSim. No hace falta editarlos manualmente.

## 11. Limitaciones actuales

- Tierra real (con pérdidas, aproximación de Fresnel o método
  asintótico de Sommerfeld) todavía no está soportada.
- Los modelos MMANA-GAL con cualquier tipo de tierra (perfecta o
  real) continúan rechazándose en la importación
  (`antsim import-mmana`); solo se importan modelos de espacio libre.
- No hay radiales ni pantallas de tierra, ni conductores enterrados
  (bajo el plano de tierra): esas geometrías se rechazan
  explícitamente.
- No se calculan patrones de radiación ni ganancia; esta versión solo
  valida impedancia de entrada.
- No existe todavía una interfaz gráfica.

## 12. Próxima etapa: tierra real homogénea

La fase 7B agregará `RealGroundEnvironment` (permitividad relativa y
conductividad como parámetros), la selección documentada del método
NEC2 correspondiente (reflexión de Fresnel frente al método asintótico
de Sommerfeld/Norton) y su propia validación cruzada con 4nec2. Sin
promesa, todavía, de aceptar automáticamente modelos MMANA-GAL con
tierra.
